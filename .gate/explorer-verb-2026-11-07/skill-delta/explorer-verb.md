## Rules
- **An explicit `--balances PATH` on follow_tip means BUILD + serve, not serve-only** (Config.balances_build set only by the explicit flag): a background `balances-build` thread rebuilds the snapshot when missing or >5760 blocks behind tip (6h re-check; 10min retry after failure or missing blk file; end_height=0 + allow_stale = accept whatever the walk reaches). The replay engine lives in tri7_core::balances_build (extracted from bin/balances.rs — one implementation, bin and daemon cannot drift; the bin is now a thin CLI over it). Writes are ATOMIC (pid-unique tmp+rename; a plain fs::write could tear a file the richlist verb or GUI reads mid-rebuild). When a wallet is configured the builder pairs wallet_utxos.json with the balances rebuild — rebuilding ONLY balances.json would break the listunspent coverage gate (height AND hash must match across BOTH snapshots).
- **The `richlist` verb is PASSIVE** (NATIVE_METHODS but not OPS_METHODS): it answers while the ops engine is still warming — that is what makes 'every node is an explorer' true. It reads through RichListCache (mtime+len keyed) so a background rebuild is visible without a restart, and labels coverage honestly: snapshot_height + covered_tip_hash + chain_tip_height (null under contention) + total_ranked; balance_tri via the COIN=1e6 rule. Ranking is balance DESC with address ASC tie-break — never HashMap order.
- **Legacy-archive seams differ per host copy — measure before trusting snapshot depth**: DNS2's archive walks to the h2201090 seam; Pi's legacy copy had an EARLY seam at h10869 (a different mirror with an early orphan branch written in), which silently capped Pi's first builder run at supply 49.5B sats instead of 222.5B. Fix: replace Pi's archive with DNS2's (984MB scp; old file kept as .old-pi-legacy) + delete Pi's index caches + restart. The builder's numbers (222,507,326,452 sats / 17,769 live UTXOs) are the known-good phase-1e ground truth — any other total means the walk stopped early.
- **Cross-building aarch64 needs the linker env var**: `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc cargo build --release --target aarch64-unknown-linux-gnu --bin follow_tip` — plain cargo build picks the host cc and dies at LINK time with "--fix-cortex-a53-843419 is only supported on AArch64" (all cargo checks pass first, so it reads like a toolchain mystery).
- **GUI consumption of richlist = the three-place rule proven again**: NATIVE_METHODS + rpc_client ALLOWED_METHODS + explorer source-priority chain (live verb first, file fallback; the fallback label must say "snapshot fallback … live daemon richlist unavailable" — the old label claiming "the daemon has no rich-list method" becomes a false statement the moment the verb ships).
- **A headless node launched by hand (PPID-1 orphan) is not a deployment**: Pi's follow_tip was an ssh-spawn that would die at reboot; give it a systemd unit with the EXACT exec args + the new flags when you touch it (Pi's unit runs as root because its seed wallet lives under /root/tri7-wallet — ProtectHome=yes would hide it; moving the wallet is deliberate future work).
