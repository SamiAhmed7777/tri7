## Spend building & signing invariants
- **`build_spend_outputs` writes `tx.vin` in (txid, n) SORTED order; every
  per-input re-verification MUST iterate that same order.** The daemon's
  sendtoaddress and the GUI send path both re-ran `verify_input` /
  `connect_inputs_check` against the UNSORTED selection list — the zip
  misaligned and every multi-input spend self-rejected with "ConnectInputs:
  prevout map misaligned with vin", while single-input spends passed. Both
  call sites now sort a copy of the selection into vin order (follow_tip
  build_wallet_tx; gui/state send build) — sort there too if you add another
  verifiers, or consume the plan's ordered list. The multi-input regression
  test is LANDED (`multi_input_spend_writes_vin_in_sorted_order_and_verifiers_follow`):
  it pins the builder's vin contract, the verifier-passes-on-sorted contract,
  AND the unsorted-selection still-fails-loudly contract — keep all three
  parities when touching the builder or verifiers.
- **A 1-input dry run proves the build, not the send path.** Before trusting
  a send refactor, exercise a REAL multi-input sendtoaddress end to end
  (build → connect check → pool accept) — the failure mode above was live for
  days behind passing dry runs.

## I2P fleet ops — i2pd on Windows (2026-11-07, sami-pc landed)
